# deploy-config (Terraform)

Declaratively manages **everything the v2 Cloud Run deploy workflow needs**, in one
`terraform apply`:

- **GitHub** (v2 repo): the `GCP_SA_KEY` secret + `GCP_PROJECT` / `GCP_REGION` variables.
- **GCP Secret Manager**: the 5 app secrets `gemini`, `db`, `redis`, `jwtpriv`, `jwtpub`,
  and grants the Cloud Run runtime service account read access to each.

The JWT RS256 keypair is **generated by Terraform** (`tls_private_key`) — you never
create or paste it. The `GCP_SA_KEY` value is a **fresh key minted for your existing
deploy service account** (v1's key keeps working), because GitHub secrets are
write-only and can't be copied out of the v1 repo.

## Prerequisites

```bash
# GCP auth (Application Default Credentials)
gcloud auth application-default login

# GitHub auth — a token with repo admin scope
export GITHUB_TOKEN="$(gh auth token)"
```

You need the **email of your existing deploy service account** (the one v1 uses):

```bash
gcloud iam service-accounts list --project <your-project>
```

## Run

```bash
cd infra/terraform/deploy-config
cp terraform.tfvars.example terraform.tfvars   # then edit it (it is gitignored)

# Keep the sensitive values out of the file — prefer env vars:
export TF_VAR_gemini_api_key='AIza...'
export TF_VAR_database_url='postgres://...'
export TF_VAR_redis_url='redis://...'

terraform init
terraform plan
terraform apply
```

After apply, run the deploy workflow: **Actions → Deploy v2 (Cloud Run) → Run**.

## Important notes

- **State is sensitive.** It contains the SA key, the JWT private key, and the app
  secret values. Use the GCS backend (uncomment it in `versions.tf`) rather than
  local state, and never commit `*.tfstate`. (`.gitignore` already blocks it.)
- **Reusing v1's secrets.** Secret ids are project-global. If your project already
  has a secret named `gemini`/`db`/`redis`, either `terraform import` it into this
  config, rename here, or point `deploy.yml` at v1's existing names instead of
  creating new ones.
- **Rotating the SA key.** `terraform apply -replace=google_service_account_key.deployer`
  mints a new one and updates the GitHub secret; the old key can then be deleted.
